# 个人用量仪表盘

仪表盘沿用现有页面布局、主题和计费展示组件，数据来自当前登录用户的消费及失败日志，不依赖前端模拟数据。无需新增表或数据库迁移。

## 接口与筛选

- `GET /api/user/dashboard/usage`：汇总、对比、小时/天/周趋势、自然日明细、模型及 Key 名称分组、可选筛选项。
- `GET /api/user/dashboard/requests`：同一筛选条件下的请求明细，`page` 从 0 开始，`size` 为 1–100。
- `GET /api/user/dashboard/requests/export`：导出全部匹配请求的 CSV，包含历史计费明细。

三个接口共用参数解析和日志筛选，用户 ID 只取认证上下文。支持 `range=24h|7|30|90|custom`、`timezone`、`model`、`token`、`stream=stream|nonstream`、`effort`、`status=success|error|400..599`、日志 ID `search`、首响应阈值 `min_first`（毫秒）。自定义范围使用 Unix 秒 `start/end`；时间边界为 `[start,end)`。

`24h` 是滚动 24 小时；7/30/90 天从本地日历日期零点开始，截止当前时间。24h 和自定义范围与前一等长区间对比；7/30/90 天与上一周期同时段对比。趋势点返回各自的当前及上一周期时间边界，点击哪一期就查询哪一期的请求。请求明细与导出固定使用当前图表的截止时间。

最多查询最近 180 天；上一周期超出范围时不计算对比。自动粒度为：不超过 48 小时按小时，超过 45 天按周，其余按天。显式小时粒度超过 168 小时时回退到天。一次扫描最多读取当前用户 300,000 条原始日志（包含对比区间、筛选前计数），超限明确报错，要求缩短范围；CSV 在完整查询成功后才返回，避免下载残缺数据。

## 指标口径

- 消费、输入输出和缓存量只统计成功消费日志；失败单独计数。成功率与失败率只描述已记录的请求，消费或错误采集关闭时隐藏这些比例。
- 平均耗时、总耗时 P95 使用耗时大于零的成功请求；首响应 P50/P95 只使用成功流式请求，且 `0 < first_response <= request_time`。无有效样本显示“—”。分位数使用排序后的线性插值。
- 首响应是首次收到上游数据，不等同于严格的首个文本 Token。输出速度为 `completion_tokens / ((request_time - first_response) / 1000)`，展示有效样本中位数，并标明估算。
- 缓存净节省复用 `GetIncreaseTokens`，使用日志中的历史缓存倍率、输入价格、分组、服务层级和长上下文倍率计算。缓存写入溢价会抵扣节省，结果可能为负数。按次、免费或缺少计价快照的请求不伪造估值；页面同时显示计价覆盖数。该值为额度取整前估算，不是退款。
- Key 以日志中的名称分组：同名合并，改名前后分开；不声称能按已删除/改名令牌的唯一 ID 还原历史。
- 原始 `quota` 为内部额度。聚合 CSV 明确标记额度；逐次请求 CSV 复用既有日志导出格式，费用为 USD。界面金额仍通过项目 `renderQuota` 展示。
- 新失败日志统一记录毫秒并写入 `request_time_unit=ms`；旧失败日志没有该标记，按原来的秒解释。仪表盘、原日志页面及日志 CSV 均兼容。

视图保存在当前浏览器，按用户 ID 隔离；保存的是筛选和图表偏好。自动刷新每 30 秒运行，页面隐藏时暂停，且不会关闭请求详情。历史清理、曾经关闭日志采集、缺少计时字段等情况无法事后补齐。
